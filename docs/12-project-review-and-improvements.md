# 프로젝트 검토 및 보완 사항

검토일: 2026-11-13

검토 대상은 `Sichan`의 알고리즘, 실험 도구, 저장된 결과와 로컬 데모다. 구현 기준은 [`9c03abd`](https://github.com/apple4232/Algorithm-project/tree/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8)이며, 이후 로컬 설명 HTML 추가는 평가 대상에서 제외했다. `main`과 구현 브랜치의 진행 상태가 다르므로 아래 근거 링크는 검토한 커밋에 고정했다.

이 문서는 검토 결과와 후속 작업을 정리한다. 체크하지 않은 항목은 제안이며, 해당 수정이나 추가 실험이 완료되었다는 뜻은 아니다.

## 1. 종합 판단

**알고리즘 수업의 구현·비교 프로젝트라는 기준으로는 기본 구성이 충분하다. 우선 보완할 부분은 실험 경계의 검증과 연구 결론의 범위다.** 실제 평가는 과목의 평가 기준에 따라 달라질 수 있다.

현재 결과는 고정된 합성 창고와 기록된 실행 환경에서 작은 작업에는 DP, 큰 작업에는 NN+2-opt를 사용하는 개수 기반 규칙의 효과를 뒷받침한다. 다섯 workload 특성을 함께 활용해야 더 좋은 선택을 할 수 있다는 근거는 아직 부족하다.

다중 작업자나 혼잡을 추가하기보다 현재 범위에서 선택 규칙이 언제 유효한지 마무리하는 것이 우선이다.

## 2. 확인한 근거와 충분한 부분

| 확인 항목 | 검토 결과 |
|---|---|
| 자동 테스트 | Python 3.13.5에서 37개 모두 통과 |
| 작업 생성 재현성 | 동일 설정으로 재생성한 4,050개 작업이 저장 데이터와 일치 |
| 저장 경로 검증 | 평가 candidate/request 기록의 경로 34,425건에서 끝점·필수 위치·통로 연결·거리 일치 검증 통과 |
| 정확해와의 일관성 | 정확해가 있는 평가 작업 1,350개에서 정확 방법 간 거리 불일치 및 정확해보다 짧은 반환 거리 없음 |
| 코드 지문 | 저장된 선택 규칙의 소스 지문이 검토 시점의 `picking/`, `experiments/`와 일치 |
| 정책 비교 | 개수 정책의 평균 거리 절감 1.426m, seed 그룹 bootstrap 95% 구간 1.229~1.630m |

위 결과는 검토 시점의 코드와 저장 자료에 대한 확인이다. 전체 성능 실험을 새로 실행한 결과는 아니다.

유지할 만한 설계는 다음과 같다.

- Dijkstra 거리 전처리와 방문 순서 알고리즘을 분리하여 공통 거리표로 비교한다.
- 경로 복원 후 실제 통로와 필수 위치 방문 여부를 검증한다.
- 정확 방법의 중단과 최적해 증명을 구분한다.
- 요청 후보의 실패와 실제 반환한 NN 대체 경로를 따로 기록한다.
- 같은 seed에서 파생된 작업을 같은 개발·평가 그룹으로 묶는다.
- 평가 전에 규칙을 고정하고, 합성 데이터와 단일 환경이라는 한계를 결과 문서에 명시한다.

## 3. 우선순위 요약

| 우선순위 | 작업 | 완료 기준 |
|---|---|---|
| P1 | 연구 주장과 선택 규칙의 표현 정리 | 단일 분기 규칙이 검증한 범위를 보고서·발표에서 동일하게 설명 |
| P1 | DP 선택 경계 주변 추가 실험 | n=13·14와 복수 시간 예산에서 완료율·거리·시간 기록 |
| P1 | 실제 사용 경로의 전체 시간 비교 | 고정 정책 직접 실행과 필요한 정보만 계산하는 선택 정책 비교 |
| P2 | 절감 효과의 크기 함께 보고 | 절감 거리·상대 절감률·추가 계산 시간을 같은 표에 제시 |
| P2 | Conveyor-Aware 조건별 분석 | 같은 작업의 승·무·패와 거리 차이를 크기·출발점·패턴별 집계 |
| P2 | 현재 상태 안내 정리 | README 도입부와 뒤쪽의 로컬 데모 구현 안내 일치 |

P1은 현재 연구 질문과 결과를 더 설득력 있게 연결하는 작업이다. P2는 기존 자료를 활용한 해석·문서 보완이다. 이번 확인에서 치명적인 경로 정확성 오류는 발견하지 못했다.

## 4. P1 — 먼저 보완할 사항

### 4.1 다섯 특성의 효과와 단일 분기 규칙을 구분한다

**현재 상태:** 학습기는 여러 특성을 후보로 비교하지만 최종 규칙에는 특성 하나의 분기만 사용한다. 개수, 수치 특성, 패턴 포함 정책 모두 `n <= 13.5`이면 DP, 그 외에는 NN+2-opt를 선택했다.

**부족한 점:** 현재 구조는 “작업이 크고 분산도가 높은 경우”처럼 특성 간 조합을 표현하지 못한다. 추가 특성의 이득이 관찰되지 않은 이유가 데이터인지, 특성인지, 규칙의 표현 한계인지는 분리하지 못했다. 기존 결과 문서는 이득이 관찰되지 않았다는 점을 이미 인정하고 있다.

**할 일:**

- [ ] 보고서와 발표의 결론을 “이 데이터와 단일 분기 규칙에서는 개수 외 특성의 추가 이득을 확인하지 못했다”로 통일한다.
- [ ] 추가 검증이 필요하면 작은 작업의 DP 선택을 먼저 고정하고, 큰 작업에서 공간 특성으로 휴리스틱을 선택하는 간단한 2단계 규칙을 개발 데이터로 비교한다.
- [ ] 규칙을 수정한 뒤 최종 성능을 주장할 때는 새 평가 seed를 확보한다. 이미 확인한 평가 결과는 탐색 분석으로 구분한다.

**미보완 시 영향:** 현재 규칙의 결과를 근거로 공간 특성이 일반적으로 불필요하거나 다섯 특성의 공동 효과를 검증했다고 설명할 수 없다.

근거: [학습 코드](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/experiments/analysis.py#L114-L139), [저장된 규칙](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/results/full/rules.json).

### 4.2 n=13·14와 시간 예산을 추가 검증한다

**현재 상태:** 실험 크기는 3, 5, 7, 8, 10, 12, 15, 20, 50이다. 저장된 평가 요청에서 DP는 n=12의 225건을 모두 완료했고 중앙값은 약 26.6ms였다. n=15의 225건은 모두 200ms 예산에서 시간 초과였다.

**부족한 점:** 선택 경계 13.5는 관측한 12와 15 사이의 중간값이다. n=13·14의 실제 완료율과 실행 시간은 측정하지 않았다. 0.2초도 운영 요구에서 정한 예산이 아니므로 경계가 예산에 얼마나 민감한지 확인할 필요가 있다.

**할 일:**

- [ ] n=12~15를 포함하는 경계 실험을 추가하고 같은 작업에서 후보를 비교한다.
- [ ] 예를 들어 0.05·0.2·1.0초처럼 예산을 사전에 정해 전체 요청 완료율, 시간 중앙값·p90, 반환 거리, 대체 경로 여부를 기록한다.
- [ ] 경계 부근은 같은 작업을 여러 번 실행해 시간 변동을 확인하고 실행 환경과 반복 횟수를 남긴다.
- [ ] 경계는 개발 데이터로 정하고 새 평가 seed에서 확인한다. 기존 결과 디렉터리는 보존한다.

**미보완 시 영향:** n=13·14에 현재 규칙을 적용할 때 예산 내 완료율을 근거 있게 설명하기 어렵다.

근거: [실험 조건 및 DP 결과](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/docs/09-role-b-results.md), [전체 요청 원자료](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/results/full/eval-request.jsonl).

### 4.3 필요한 계산만 포함한 정책 실행 시간을 비교한다

**현재 상태:** 정책 평가는 모든 정책에 대해 거리표와 전체 특성을 준비하고, 이후 `run_request()`에서 거리 전처리를 다시 수행한다. 고정 정책과 개수 정책도 이 비용을 부담한다. 기존 방법론 문서는 이 실험용 구조를 명시하고 있다.

**부족한 점:** 고정 정책은 선택 특성이 필요 없고 개수 정책은 위치 수만 있으면 선택할 수 있다. 현재 시간은 공통 처리 과정을 적용한 측정값이며, 실제 사용할 최소 처리 경로의 시간과 차이가 있다.

**할 일:**

- [ ] 고정 NN+2-opt는 직접 요청을 실행하는 기준선을 추가한다.
- [ ] 개수 정책은 검증·중복 통합 후 위치 수로 선택하고, 공간 특성이 필요한 정책만 해당 특성을 계산한다.
- [ ] 공간 특성을 계산한 거리표는 경로 탐색에도 재사용하여 중복 전처리를 없앤다.
- [ ] 모든 정책에 동일한 총예산을 적용하고 검증부터 경로 복원까지 측정한다. 캐시 조건도 동일하게 맞춘다.
- [ ] 공유 전처리 변경 시 예산 소진, 실패 상태, 대체 경로, 경로 검증을 유지하는 테스트를 보강한다.

**미보완 시 영향:** 현재 정책 시간만으로 실제 사용 시 추가 계산 비용이나 속도상 이점을 판단하기 어렵다.

`picking/` 또는 `experiments/`를 수정하면 저장된 규칙의 코드 지문과 달라진다. 검사를 우회하지 말고, 새 코드로 측정·학습·평가한 결과를 별도 디렉터리에 남긴다.

근거: [정책 실행 코드](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/experiments/__main__.py#L29-L64), [기존 시간 측정의 한계](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/docs/08-role-b-experiments.md#L49-L59).

## 5. P2 — 기존 자료로 보완할 사항

### 5.1 개선 폭을 절대값과 상대값으로 함께 제시한다

저장된 평가 정책 2,025개 작업의 원자료를 재집계한 값은 다음과 같다.

| 지표 | 고정 NN+2-opt | 개수 기반 정책 |
|---|---:|---:|
| 평균 이동거리 | 168.29m | 166.86m |
| 고정 정책 대비 평균 절감 | — | 1.43m |
| 전체 거리 기준 상대 절감률 | — | 약 0.85% |
| 예산 내 완료 작업 | 2,025 / 2,025 | 2,025 / 2,025 |
| 기존 실험 처리 과정의 총시간 중앙값 | 2.41ms | 3.47ms |

상대 절감률은 `동일 작업의 평균 절감 거리 / 고정 정책 평균 거리 × 100`이다. 작업별 절감률의 평균과는 다른 지표다.

- [ ] 결과 표에 절감 거리·상대 절감률·추가 계산 시간을 함께 제시한다.
- [ ] 평균과 중앙값을 구분하고, paired 평균 차이의 seed 그룹 bootstrap 구간 1.23~1.63m를 함께 설명한다.
- [ ] 실제 이동 속도와 작업량을 측정하기 전에는 노동시간·생산성 향상으로 환산하지 않는다.

미보완 시에는 개선의 존재와 실용적인 크기를 구분하기 어렵다.

근거: [정책 비교 집계](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/results/full/eval-policy-comparison.json), [정책 원자료](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/results/full/eval-policies.jsonl).

### 5.2 Conveyor-Aware의 조건별 승패를 설명한다

계수 0.5의 candidate 평가에서 CA-minus+2-opt는 NN+2-opt보다 평균 거리가 약 0.99m 길었다. 하지만 같은 작업별 비교에서는 282건에서 더 짧고, 1,357건에서 같고, 386건에서 더 길었다. 전체 평균으로는 조건별 차이가 가려진다.

- [ ] 물건 수·출발점·패턴별로 동일 작업의 승·무·패와 평균 거리 차이를 집계한다.
- [ ] 개선 사례와 악화 사례를 함께 제시한다. 사례 선택은 전체 성능의 대표값과 구분한다.
- [ ] 계수 0.5는 작은 개발 파일럿에서 CA-minus를 기준으로 정한 공통값이라는 한계를 유지한다.
- [ ] 계수를 더 튜닝한다면 개발 데이터만 사용하고, 수정된 정책은 새 평가 seed로 확인한다.

미보완 시에는 CA가 유용했던 조건을 설명하지 못하고, 특정 계수의 결과를 방법 전체의 우열로 확대할 수 있다.

근거: [후보 평가 원자료](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/results/full/eval-candidate.jsonl), [계수 선정 과정](https://github.com/apple4232/Algorithm-project/blob/9c03abd7e3da0dbaa55c2bf06c297071a2dcf9c8/docs/08-role-b-experiments.md#L43-L47).

## 6. 연구 결과에 계속 명시할 한계

- 창고 구조와 컨베이어 위치가 하나로 고정되어 있다. 다른 창고에서의 일반화는 검증하지 않았다.
- 평가 작업 2,025개는 독립 표본 2,025개를 뜻하지 않는다. 재표본추출 단위는 15개 평가 seed 그룹이다.
- 반사 쌍 F는 출발점과 물건 사이 거리도 바꾸므로 컨베이어 거리만의 인과 효과로 해석하지 않는다.
- 패턴과 분산도·거리·밀도는 함께 변할 수 있다. 패턴별 차이는 우선 기술적 비교로 보고한다.
- 큰 작업에서 후보 중 가장 짧은 경로는 전역 최적해와 다르다. 최적해가 없는 경우 best-known 기준 차이로 표시한다.
- 시간 제한은 협력적으로 검사한다. 엄격한 실시간 종료나 전체 프로세스 메모리 상한을 보장하지 않는다.

## 7. 권장 마무리 순서와 결론 문구

1. 현재 입증 범위에 맞춰 보고서·발표 문구를 정리한다.
2. n=13·14와 시간 예산 민감도를 추가 확인한다.
3. 필요한 계산만 포함한 전체 요청 시간을 재측정한다.
4. 기존 자료로 절감률과 CA 조건별 결과를 보완한다.
5. 다섯 특성의 공동 효과를 계속 연구할 경우에만 간단한 2단계 규칙과 새 평가 데이터를 추가한다.

현재 자료로 사용할 수 있는 결론은 다음과 같다.

> 고정된 합성 창고와 기록된 실행 환경의 0.2초 예산에서, 개수 기반 선택은 고정 NN+2-opt보다 평균 이동거리를 약 0.85% 줄였다. 개수 외 공간 특성의 추가 이득은 현재의 단일 분기 규칙에서는 확인되지 않았다.

검토에서 실행하지 않은 항목: 브라우저 직접 시연, 전체 성능 실험 재실행, 외부 논문 원문 대조. 코드와 기존 실험 결과 파일은 변경하지 않았다.
