# 큰 피킹 작업의 한 곳씩 → 6곳 묶음 순서 개선

2026-11-19

팀 소개에서는 제안 방법을 **한 곳씩 → 6곳 묶음 순서 개선**으로 부른다. 기존 NN+2-opt 경로에서 시작해 선반 하나의 방문 순서를 옮기는 재삽입을 한 번 수행하고, 연속 여섯 선반의 순서를 구간 DP로 다시 계산하는 조합이다. 비교 방법은 **한 곳씩 순서 개선 · 2회**이다. 두 방법은 초기 경로가 같으며 두 번째 단계의 연산이 다르다.

방문 위치가 많아 전체 정확 DP를 실행하기 어려운 요청에서, NN+2-opt 경로에 재삽입과 짧은 구간의 정확 계산을 순서대로 적용한다. 고정 창고의 선반 15·20·50곳 작업을 대상으로 한다.

## 방법과 적용 범위

1. 공통 최단거리 행렬에서 NN+2-opt 경로를 만든다.
2. 초기 방문 순서의 각 위치를 한 번씩 처리한다. 해당 위치를 제거하고 다른 모든 삽입 지점을 비교해 가장 짧아지는 위치로 옮긴다.
3. 연속한 여섯 위치의 양옆 경계를 고정하고 기존 부분집합 DP로 내부 순서를 계산한다. 세 위치씩 이동하며 한 번 순회하고 마지막 구간도 포함한다.
4. 전체 거리가 감소할 때만 채택한다. 시간 중단 시 마지막으로 채택한 방문 순서를 보존하고 실행기에서 실제 경로를 복원·검증한다.

출발점과 컨베이어를 고정한다. 중복 요청과 끝점 요청은 기존 Task 처리 규칙을 따른다. 여섯 개 이하에서는 한 구간을 계산한다. DP 메모리 한도에 걸린 구간은 건너뛰고 종료 원인을 기록한다. 전처리 중 시간 초과로 초기 경로를 확보하지 못하면 기존 실행기의 경로 없는 timeout 응답을 따른다.

계산 예산은 기존 실행기와 같은 협력적 시간 제한이다. 경로 복원·검증의 시간을 실제 총시간에 포함하며 초과 여부를 기록한다. 엄격한 실시간 상한의 보장은 추가 검증이 필요하다.

## 새 작업 실험

시드 3000~3029의 30개 그룹에서 위치 수 세 가지, 배치 다섯 가지, 출발점 세 가지를 조합한 1,350개 작업을 생성했다. 기존 full 작업의 위치 집합과 중복이 없음을 검사했다. 이 실험에서는 시드 홀짝을 이용한 선택기 학습을 수행하지 않고 30개 그룹 전체를 고정된 방법의 확인에 사용했다.

각 작업에서 NN+2-opt, 재삽입 한 번, 재삽입 두 번, 재삽입 후 구간 DP를 무작위 순서로 실행했다. 요청당 200ms에 전처리, 탐색, 실제 경로 복원·검증을 모두 포함했다. Python 3.13.5, macOS arm64 한 환경에서 작업·방법마다 한 번 측정했다.

| 방법 | 평균 거리 | 전체 시간 중앙값 | 전체 시간 95백분위수 |
| --- | ---: | ---: | ---: |
| NN+2-opt | 228.317m | 2.47ms | 7.73ms |
| 재삽입 한 번 추가 | 227.111m | 2.71ms | 9.09ms |
| 재삽입 두 번 추가 | 227.043m | 2.92ms | 10.45ms |
| 재삽입 후 구간 DP 추가 | 226.637m | 3.44ms | 11.26ms |

총 5,400회가 모두 완료됐고 기록된 예산 초과는 0건이었다. 두 단계 방법은 NN+2-opt 대비 평균 1.680m, 재삽입 두 번 대비 0.406m 줄였다. 후자의 30개 시드 그룹 부트스트랩 95% 신뢰구간은 0.290~0.527m였다. 같은 작업의 거리를 짝지어 비교했다.

위치 수 15·20·50에서 NN+2-opt 대비 평균 절감은 각각 2.204m, 1.964m, 0.871m였다. 모든 작업에서 두 단계 결과가 재삽입 한 번 및 초기 경로보다 길어지지 않았음을 검사했다.

## 해석

두 번째 개선 단계에 구간 DP를 쓰면 재삽입을 다시 수행하는 것보다 추가 거리 절감이 관측됐다. 거리의 실용적 가치는 추가 계산 비용과 함께 판단해야 한다. 이 조합의 세계 최초성이나 다른 창고에서의 성능은 별도 선행연구·실험이 필요하다.

특정 배치에 따라 알고리즘을 선택하는 규칙은 이번 구현에 포함하지 않았다. A~H 관점의 후속 분석에서는 배치와 출발점에 따른 절감의 차이를 설명하고, 조건을 새로 선택한다면 별도 시드로 평가해야 한다. 고정된 구간 크기 6·간격 3이 최선인지도 아직 확인하지 않았다.

## 재현과 검증

- 실행 명령은 프로젝트 루트에서 `python3 -m experiments.two_stage results/two-stage-rerun`이다. 새 출력 폴더를 지정한다.
- 단일 작업 CLI에서는 `python3 -m picking --algorithm nn+2opt+reinsert+segment-dp --budget-seconds 0.2`를 사용한다.
- [작업별 결과](../results/two-stage-fresh/requests.jsonl)와 [요약 및 환경](../results/two-stage-fresh/summary.json)에 원자료를 저장했다.
- [실험 코드](../experiments/two_stage.py), [알고리즘](../picking/algorithms.py), [회귀 테스트](../tests/test_two_stage.py)에 구현이 있다.
- 전체 테스트 40개가 통과했다. 작은 작업의 정확 DP와의 일치, 중복·끝점 요청, 중단 시 유효 순서 보존, 구간 DP 내부 강제 중단 시 실행기의 검증된 경로 반환을 포함한다.

실험은 단일 합성 창고와 단일 실행 환경에 한정된다. 반복 시간 측정과 현장 작업시간 절감은 후속 검증 대상이다.

## 반복 시간 측정과 팀 소개 데모

새 시드 작업에서 위치 수별 20건씩 총 60건을 고정 추출했다. 각 작업을 네 방법으로 10번씩 실행했으며 매 반복마다 방법 순서를 섞었다. 2,400회 모두 완료됐고 200ms 예산 초과는 없었다. 같은 작업·방법의 거리는 10회 모두 일치했다.

| 방법 | 전체 시간 중앙값 | 전체 시간 95백분위수 |
| --- | ---: | ---: |
| NN+2-opt | 2.41ms | 7.57ms |
| 재삽입 한 번 추가 | 2.64ms | 8.95ms |
| 재삽입 두 번 추가 | 2.84ms | 10.15ms |
| 재삽입 후 구간 DP 추가 | 3.34ms | 11.13ms |

이는 선택된 60개 작업의 반복 측정이다. 시드별 거리 효과의 검증은 앞의 1,350건 결과를 사용한다. [반복 결과](../results/two-stage-repeat/summary.json), [측정 기록](../results/two-stage-repeat/requests.jsonl), [재현 스크립트](../experiments/two_stage_timing.py)에 근거를 남겼다. 반복 실험은 출력 폴더가 없는 상태에서 프로젝트 루트의 `python3 -m experiments.two_stage_timing`으로 실행한다.

데모 실행은 `python3 -m demo --port 8766`이다. 브라우저에서 `http://127.0.0.1:8766`을 열고 시나리오 I ‘제안 알고리즘’을 선택한 뒤 경로 재계산을 누른다. 기본 비교는 재삽입 두 번과 재삽입 후 구간 DP이다. 같은 물건 집합에서 위치 수·배치·출발점을 변경하며 비교한다. 위쪽 경로 카드의 재계산 시간과 아래쪽 기존 저장 기록의 측정 시점을 구분해 소개한다.

기본 작업 101:20:random-stow-like:0에서 재삽입 두 번은 248m, 두 단계는 240m로 브라우저에서 확인했다. 기존 NN+2-opt는 저장 기록에서 256m이다. 이 작업은 동작 설명용 예시이며 평균 효과는 전체 작업의 결과를 사용한다. 세 가지 새 방법 모두 알고리즘 선택 목록에서 선택할 수 있다.
