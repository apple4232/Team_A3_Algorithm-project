# 데모 작업 대화·진행 기록

작성일: 2026-11-20  
이 문서는 현재 대화에서 확인할 수 있는 요청과 진행 상황을 정리한 **요약**이다. 대화 원문 전체를 그대로 저장한 기록은 아니며, 이전 대화에서 확인하지 못한 내용은 추정하지 않는다.

## 목적과 배경

창고 피킹에서 물건을 방문하는 순서를 여러 알고리즘으로 비교하고, 저장된 실험과 현재 재계산 결과를 이해하기 쉽게 보여주는 로컬 데모를 개선했다. 사용자는 특히 결과표의 집계 범위, 알고리즘의 실제 이름과 설계 의도, 계산 설정의 의미를 명확히 해 달라고 요청했다.

## 대화에서 정한 데모 동작

- 물건 배치 이름을 ‘가까운 통로에 모아 배치’, ‘창고 전체에 흩어 배치’ 등으로 풀어 썼다.
- 중복된 작업 선택 메뉴를 없앴다. 필터에 해당하는 작업이 여러 개면 첫 번째 작업을 지도에 표시하며, 시드 선택으로 표시할 작업을 바꿀 수 있다.
- 개발 데이터는 선택 규칙을 만드는 데, 평가 데이터는 그 규칙을 만들 때 사용하지 않은 배치에서 확인하는 데 쓰인다고 안내한다. 둘 다 합성 데이터다.
- 3번 표는 **지도 A에 표시된 작업 하나**의 알고리즘별 결과다. 시나리오 F·H처럼 B의 작업이 다르면 B의 결과표도 별도로 표시한다.
- 4번 표는 선택한 시드와 무관하게 데이터 구분·위치 수·물건 배치·출발점에 맞는 **전체 시드**의 결과를 집계한다. 거리와 시간은 제한 시간 안에 완료된 결과의 중앙값이다. F·H에서는 짝을 이룬 B 작업도 별도로 집계한다.
- 시드가 전체일 때는 3번에 조건에 맞는 첫 번째 작업을 보여준다. ‘전체 시드’는 평균이 아니라 작업들의 집계 범위를 의미한다.
- 지도에는 S(출발점), C(도착점/컨베이어), 계획된 방문 순서를 표시한다. 애니메이션은 경로 설명용으로 실제 작업 시간이 아니다.
- NN은 가까운 물건부터 고르는 간단한 비교 기준이다. NN과 거리 차이는 각 방법의 거리에서 NN 거리를 뺀 값으로, 음수면 NN보다 짧다. NN이 최적해라는 뜻은 아니다.

## 재계산과 결과 기록

‘전체 재계산’은 현재 필터에 맞는 전체 시드와 모든 알고리즘을 순서대로 실행하며, F·H에서는 각 시드의 반대편 작업도 계산한다. 진행 막대와 완료 건수를 보여주고, 취소를 누르면 실행 중인 알고리즘 한 건이 끝난 뒤 중단한다. 미완료 결과는 적용하지 않고 이전 결과를 유지한다.

계산을 마치면 3번에 현재 작업의 재계산 결과를, 4번에 전체 시드의 재계산 집계를 표시한다. 같은 조건에서 시드만 변경해도 재계산 결과가 유지된다. 완료된 재계산의 측정 기준은 전체 요청 시간으로 전환된다. ‘저장 결과로 돌아가기’로 저장된 실험을 다시 볼 수 있다.

재계산 결과는 현재 페이지에서 쓰는 임시 결과이며, 기존 실험 파일을 덮어쓰지 않는다. 0.2초 기본 제한은 **작업 한 건의 알고리즘 한 번 실행마다** 적용된다. 시간 검사는 협력적으로 이루어져 실제 시간이 조금 초과될 수 있다. CA 계수는 CA 계열이 다음 위치의 점수를 계산할 때 도착점까지의 거리에 적용하며, 0이면 그 항을 반영하지 않는다.

기존 데이터에 없던 세 알고리즘에 대해 작업 4,050개 × 후보 탐색·전체 요청 2종 × 3개 알고리즘으로 24,300건을 추가 측정했다. 결과는 원본과 별도의 `results/full/*-additional.jsonl` 네 파일에 두고 데모가 함께 읽도록 했다. 기록된 상태는 모두 완료였고 보고된 예산 초과는 없었다. 이 측정은 원본과 시점·환경이 다를 수 있으므로 시간 수치를 직접 비교할 때 주의한다.

## 제안 알고리즘

표시 명칭은 **NN + 2-opt + Reinsertion + Segment DP**다.

1. NN과 2-opt로 기본 경로를 만든다.
2. Reinsertion(재삽입)으로 방문 지점 하나씩 다른 자리에 옮겨 보며 경로가 짧아지면 적용한다.
3. 연속된 최대 6곳을 묶어 앞뒤 경계를 고정하고, 구간 DP로 그 안의 방문 순서를 계산한다. 묶음은 3곳씩 옮겨 가며 마지막 구간도 확인한다.
4. 전체 거리가 줄어드는 변경만 채택한다. 계산 중단이나 자원 제한은 결과 상태에 반영한다.

전체 방문 순서를 정확히 계산하기 어려운 큰 작업에서, 빠르게 만든 경로를 작은 구간별로 더 개선해 보려는 설계다. 전체 최단 경로는 보장하지 않는다. 이 방법은 데모에서 사용자가 직접 선택하며, 배치 조건에 따라 자동 선택하는 기능은 구현되지 않았다.

독립적으로 생성한 15·20·50개 위치의 합성 작업 1,350건에서, 제안 방법은 **NN + 2-opt + Reinsertion 2회**보다 평균 이동 거리가 0.406m 짧았다. 전체 요청 시간 중앙값은 2.92ms에서 3.44ms로 증가했다. 이는 한 합성 창고와 한 실행 환경의 결과로, 현장 성능이나 다른 창고에서의 개선을 보장하지 않는다. 상세 조건과 자료는 [두 단계 개선 기록](./15-two-stage-improvement.md)을 따른다.

초기 제안의 정확한 대화 원문은 이 요약에서 확인되지 않았다. 기록상 문제의식은 큰 작업에서 전체 정확 DP의 계산 부담을 피하면서 NN+2-opt 경로를 추가로 개선해 보자는 것이며, 위 실험 결과는 제안 후 확인된 근거다.

## 데모 실행

프로젝트 루트에서:

```sh
/usr/local/bin/python3 -m demo
```

브라우저에서 <http://127.0.0.1:8765/>를 연다. 다른 프로세스가 8765 포트를 사용 중이면 `--port 8766`을 추가하고 해당 포트로 접속한다. 서버를 종료하려면 터미널에서 Ctrl+C를 누른다. 이 환경에서는 기본 `/usr/bin/python3`가 macOS 개발 도구 오류를 낸 적이 있어 설치된 `/usr/local/bin/python3`를 사용했다.

서버는 시작할 때 실험 데이터를 메모리에 읽으므로 Python 서버 코드나 결과 파일을 변경한 뒤에는 서버 재시작이 필요하다. HTML·CSS·JS 변경은 페이지 새로고침으로 반영할 수 있다.

## 검증과 남은 확인

- 대화 중 `node tests/test_demo_filters.js`와 `python3 -m unittest tests.test_demo`를 실행해 통과했다. 측정 기록과 검증 시점은 이 문서 작성 시점의 새 전체 테스트 결과가 아니다.
- F 시나리오에서 양쪽 전체 시드 360건 재계산 후 시드를 바꿔도 재계산 결과가 유지되는 것, 취소와 전체 요청 시간 전환을 브라우저에서 확인했다.
- H 시나리오 전체 재계산, 모든 화면 크기의 배치, 접근성 전반은 별도 검증하지 않았다.
- 재계산 범위를 넓게 잡거나 제한 시간을 늘리면 오래 걸릴 수 있다. 제한 시간은 전체 일괄 작업 시간이 아니라 각 알고리즘 실행에 적용된다.
- 작성 시점에 수정 파일과 신규 파일이 Git 작업 트리에 남아 있다. 특히 추가 측정 JSONL과 실험 결과 폴더는 미추적 상태이므로 공유·커밋 전 포함 여부와 용량을 확인해야 한다. 기존 변경은 이 기록을 만들면서 되돌리지 않았다.

## 2026-11-20 후속 대화

- 사용자는 이후 작업에서도 진행 상황을 계속 기록해 달라고 요청했다. 이 기록을 관련 변경·검증이 끝날 때마다 갱신한다.
- 데모의 제안 알고리즘 설명에 제안 배경을 보강했다. 기존 실험의 20·50곳 작업이 **당시 설정한** 전체 DP 크기 제한에 걸렸다는 점과 이것이 DP의 절대 한계는 아니라는 점을 명시했다.
- NN + 2-opt가 빠른 기본 경로를 제공하지만 더 짧은 순서가 남을 수 있고, Reinsertion 이후 작은 연속 구간에 Segment DP를 적용해 한 곳씩 옮길 때 놓칠 수 있는 개선을 찾으려는 구조임을 설명했다.
- 기존 합성 창고 1,350개 작업의 평균 거리·시간 비교와 단일 환경이라는 한계는 그대로 유지했다.
- 검증: 설명 수정 후 `node tests/test_demo_filters.js` 통과. 화면 배치는 별도로 확인하지 않았다.

## 2026-11-20 NN 비교 기준 정리

- NN을 거리 비교 기준으로 유지한다. 예산 내 성능 지표는 NN과 비교 대상이 모두 예산 안에서 완료한 같은 작업만 포함한다.
- 전체 요청 기록에서 검증된 NN 경로가 남은 경우 시간 초과 기록도 별도의 거리 참고 지표에 포함한다. 참고 비교 건수와 그중 NN 시간 초과 건수를 함께 기록한다. 후보 탐색 기록은 검증된 경로를 저장하지 않으므로 해당 참고 지표에서 제외한다.
- 데모의 개별 작업 표는 검증된 NN 경로가 시간 초과로 반환되면 거리 차이에 참고 표시를 붙이고, 경로가 없거나 검증에 실패하면 표시하지 않는다. 최적 경로 비교도 예산 내 완료 결과만 사용한다.
- README의 현재 상태, 로컬 데모와 추가 알고리즘 목록을 갱신했다. 기존 실험 결과 파일은 재생성하거나 덮어쓰지 않았다.
- 검증: Python 전체 테스트 43개, `node tests/test_demo_filters.js`, `git diff --check` 통과. 브라우저 화면과 전체 실험 재실행은 확인하지 않았다.
