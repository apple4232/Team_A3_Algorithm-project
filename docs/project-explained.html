01. 우리 프로젝트는 무엇을 하나요?

창고에서 물건을 모두 집고 컨베이어로 가져갈 때, 덜 걸으면서 계산도 오래 기다리지 않는 방법을 찾는 프로젝트입니다.

마트에서 우유, 과자, 사과를 사야 한다고 생각해 보세요. 목록 순서대로 걷는 것과 가까운 물건부터 담는 것은 이동 거리가 다를 수 있습니다. 우리 프로그램은 이 방문 순서를 여러 방법으로 계산하고 비교합니다.

출발점 S→필요한 위치 P 전부→컨베이어 C

물건을 집는 작업을 피킹(picking)이라고 합니다. 컨베이어는 물건을 모아서 넘기는 고정된 도착점입니다. 작업자는 한 명이며, 마지막에 출발점으로 되돌아가지 않습니다.

발표에서는 이렇게“저희는 창고에서 여러 물건을 수집해 고정 컨베이어로 이동하는 문제를 다룹니다. 작업 규모와 배치가 달라질 때, 이동 거리와 계산 시간을 함께 고려해 어떤 알고리즘을 선택하면 좋은지 비교했습니다.”
기여를 정확히 말하기: 모든 알고리즘을 새로 발명했다는 주장이 아닙니다. 동일한 창고와 작업 조건에서 기존 방법과 실험 후보를 비교하고, 설명하기 쉬운 선택 규칙을 평가한 것이 핵심입니다.

03. 창고를 컴퓨터에 어떻게 표현하나요?

컴퓨터는 선반 사진만 보고 통로를 알 수 없습니다. 그래서 이동 가능한 위치를 점(노드), 두 점 사이의 통로를 선(간선), 통로 길이를 가중치로 기록합니다. 이것을 그래프라고 합니다.

고정 환경실제 구현
세로 통로10개: x = 0, 4, 8, …, 36m
가로 연결 통로y = 0, 20, 40m인 3줄에서만 좌우 이동
세로 위치 간격2m
전체 규모노드 210개 · 무방향 간선 227개 · 피킹 위치 180개
컨베이어(36, 0)으로 고정
실험 출발점(0, 0), (16, 20), (0, 40)
방향성양방향 통행 가능. A→B와 B→A의 거리가 같음

왜 직선거리를 쓰지 않나요? (0, 8)에서 (4, 8)은 직선으로 4m 떨어져 있지만, y=8에는 가로 통로가 없습니다. 아래쪽 가로 통로로 돌아가면 8+4+8=20m입니다.

05. distances.py — 거리 계산을 이해하기

다익스트라는 “두 장소 사이를 어떻게 갈까?”를 해결합니다. 물건을 어떤 순서로 모두 방문할지는 다음 단계에서 결정합니다. 이 분리가 있어야 모든 방문 순서 알고리즘이 같은 거리 조건에서 공정하게 비교됩니다.

① Task.create: 중복 요청과 끝점 정리

예를 들어 [(0,8), (0,8), (8,14)]는 물건 3개 요청이지만 방문 위치는 2곳입니다. Counter는 수량을 기록하고, required에는 위치를 한 번씩 보관합니다. 시작점이나 컨베이어에서 충족되는 요청은 internal에서 제외합니다. 수량에 따른 작업 시간이나 적재량 계산은 현재 하지 않습니다.

picking/distances.py · dijkstra() · L107–124
107def dijkstra(graph: Graph, source: Node, deadline: float | None = None,
108             clock_check: Callable[[float | None], None] = check_deadline
109             ) -> tuple[dict[Node, float], dict[Node, Node]]:
110    if source not in graph.adjacency:
111        raise InputError("출발 노드가 지도에 없습니다.")
112    distances, previous = {source: 0.0}, {}
113    queue = [(0.0, source)]
114    while queue:
115        clock_check(deadline)
116        distance, u = heappop(queue)
117        if distance != distances[u]:
118            continue
119        for v, weight in graph.adjacency[u].items():
120            candidate = distance + weight
121            if candidate < distances.get(v, inf):
122                distances[v], previous[v] = candidate, u
123                heappush(queue, (candidate, v))
124    return distances, previous
코드에서 볼 표현쉽게 읽는 방법
distances, previous = {source: 0.0}, {}출발점까지 거리는 0. previous는 나중에 길을 복원할 직전 위치 기록입니다.
queue = [(0.0, source)]아직 조사할 출발점을 (거리, 위치) 형태로 넣습니다.
while queue:조사할 위치가 남아 있는 동안 반복합니다.
clock_check(deadline)시간 제한을 확인합니다. 기본은 check_deadline이며 테스트에서 다른 함수로 바꿀 수 있습니다.
distance, u = heappop(queue)지금까지 발견한 후보 중 출발점에서 가장 가까운 위치 u를 꺼냅니다.

for v, weight in graph.adjacency[u].items():u와 직접 연결된 이웃 v와 통로 길이를 하나씩 봅니다.
candidate = distance + weight출발점→u의 거리 + u→v의 통로 길이를 계산합니다.
candidate < distances.get(v, inf)지금 찾은 경로가 기존 경로보다 짧은가? 아직 모르는 위치의 거리는 무한대로 취급합니다.
distances[v], previous[v] = candidate, u짧은 거리와 v 바로 직전의 위치 u를 저장합니다.
heappush(queue, (candidate, v))v를 앞으로 조사할 후보로 넣습니다.
return distances, previous최단 거리와 경로 복원 정보를 반환합니다.

손으로 따라가기

설명용 지도에 S–A=4, S–B=1, B–A=1, A–C=2, B–C=7이라는 통로가 있다고 해봅시다. 모두 양방향입니다.

순서꺼낸 위치갱신 내용
시작S, 거리 0A=4, B=1 기록
다음B, 거리 1A=min(4,1+1)=2, C=1+7=8
다음A, 거리 2C=min(8,2+2)=4
마지막C, 거리 4S→B→A→C, 총 4. 큐의 오래된 기록은 나중에 건너뜀

② prepare_distances: 거리표 준비

picking/distances.py · prepare_distances() · L127–139
127def prepare_distances(graph: Graph, task: Task,
128                      deadline: float | None = None) -> DistanceTable:
129    if task.conveyor != graph.conveyor:
130        raise InputError("작업의 컨베이어가 환경과 다릅니다.")
131    locations = tuple(sorted({task.start, task.conveyor, *task.required}))
132    matrix, predecessors = {}, {}
133    for source in locations:
134        distances, previous = dijkstra(graph, source, deadline)
135        if any(target not in distances for target in locations):
136            raise UnreachableError("S, 필수 위치, C가 같은 연결 요소에 있어야 합니다.")
137        matrix[source] = MappingProxyType({p: distances[p] for p in locations})
138        predecessors[source] = MappingProxyType(previous)
139    return DistanceTable(graph, task, MappingProxyType(matrix), MappingProxyType(predecessors))

locations는 출발점·물건·컨베이어를 중복 없이 모은 목록입니다. 각 위치를 출발점으로 다익스트라를 실행하고, 필요한 위치끼리의 거리만 matrix에 저장합니다. 하나라도 갈 수 없다면 UnreachableError로 알립니다.

DP: 같은 부분 문제를 다시 계산하지 않기

“A와 B를 방문하고 B에서 끝난 상태”까지 오는 길은 여러 개일 수 있습니다. 그러나 이후의 최선 경로를 고를 때는, 그 상태까지 가장 짧게 온 기록 하나만 있으면 됩니다. 방문한 위치 집합 M + 마지막 위치 j를 한 상태로 저장하는 것이 부분집합 DP입니다.

F[M,j] = M의 위치를 모두 방문하고 j에서 끝나는 최소 거리
F[{j},j] = d(S,j)
F[M,j] = minᵢ { F[M−{j},i] + d(i,j) }
최종 답 = minⱼ { F[전체,j] + d(j,C) }

처음에는 S에서 물건 하나로 가는 거리만 저장합니다. 이후 작은 방문 집합에서 큰 방문 집합으로 계산을 확장합니다. 마지막에는 반드시 컨베이어까지의 거리를 더해 비교합니다.

08. 2-opt — 만든 순서를 다듬기

이미 만든 경로에서 물건 방문 순서의 일부를 뒤집습니다. 뒤집었을 때 거리가 짧아지면 바꾸고 처음부터 다시 살펴봅니다. 출발점 S와 컨베이어 C는 고정합니다.

S → A → B → C → D → E → 컨베이어
↓ 일부 순서 뒤집기
S → A → D → C → B → E → 컨베이어

양방향 지도에서는 B→C→D와 D→C→B의 내부 거리 합이 같습니다. 그래서 경계의 두 연결 A–B, D–E를 A–D, B–E로 바꿀 때의 거리 차이만 먼저 확인할 수 있습니다.

변화량 Δ = d(A,D) + d(B,E) − d(A,B) − d(D,E)
Δ가 음수면 짧아질 가능성이 있으므로 전체 거리도 다시 확인
코드에서 볼 표현쉽게 읽는 방법

before / after뒤집는 구간의 바로 앞과 뒤 위치. 맨 앞뒤라면 S와 C입니다.
delta < -epsilon아주 작은 소수 오차를 제외하고 실제로 줄어드는지 확인합니다.
order[:i] + list(reversed(order[i:j + 1])) + order[j + 1:]앞부분은 유지하고 선택 구간만 뒤집고 뒷부분을 붙입니다.

Seed는 물건 위치를 어떻게 정하나요?

여기서 물건 배치는 고정된 선반 중 이번 주문에서 방문할 위치를 고르는 것입니다. 선반이나 통로 자체를 옮기지 않습니다. 물건 3개라는 말도 수량 3개가 아니라 서로 다른 방문 위치 3곳을 뜻합니다.

배치 유형으로 후보 구역 결정→Seed로 위치 추첨→출발점 3가지로 작업 생성

Seed는 같은 추첨을 다시 할 수 있게 하는 번호입니다. 실제 코드는 Seed만 쓰지 않고 버전·위치 수·배치 이름을 함께 넣습니다.

예: Seed 101 · 위치 3개 · 군집형
rng = random.Random("v1:101:3:clustered")

  2. 그 구역의 선반 위치 54곳에서 중복 없이 3곳을 뽑습니다. 전체 무작위형은 180곳, 방향형은 뒤쪽 90곳이 후보입니다.
  3. 앞에서 생성한 위치 조합과 같으면 다시 뽑습니다. 최대 1,000회 안에 새 조합을 만들지 못하면 오류로 중단합니다.
  4. 선택한 물건 위치는 그대로 두고 출발점을 앞쪽 (0,0), 중앙 (16,20), 가장자리 (0,40)로 바꾸어 작업 3개를 만듭니다.

반사 쌍은 별도의 v1:101:3:paired 추첨에서 왼쪽 5개 통로의 위치를 고른 뒤, (x,y) → (36−x,y)로 뒤집은 짝을 만듭니다. 짝의 물건 수와 위치 간 구조는 같고 컨베이어·출발점과의 관계가 바뀝니다.

같은 Seed만으로 모든 배치가 같아지는 것은 아닙니다. 물건 수나 배치 유형이 다르면 추첨 기준도 다릅니다. 동일한 코드·생성 설정·생성 순서라면 결과가 재현됩니다. 중복 조합을 다시 뽑는 처리가 있어 생성 목록과 순서를 바꾸면 같은 Seed의 결과도 달라질 수 있습니다.

왜 물건 배치를 여러 종류로 나눴나요?

물건 수가 같아도 한 구역에 모인 주문과 창고 전체에 흩어진 주문은 이동 모양이 다릅니다. 개수만으로 설명되지 않는 공간 조건에서도 방법의 차이가 나타나는지 확인하려고 나눴습니다. 특정 유형에서 특정 알고리즘이 반드시 좋다는 뜻은 아닙니다.

군집형좁은 통로 구역에 물건이 모였을 때 방문 순서 개선 효과를 살펴봅니다.좁은 구역의 주문을 나타내는 합성 조건입니다. n=50이면 후보 54곳 중 50곳을 방문하여 밀도도 높아집니다.

Seed를 왜 개발용과 평가용으로 나누나요?

연습문제로 방법을 정한 뒤 다른 문제로 확인하는 것과 같습니다. 짝수 Seed에서는 어떤 알고리즘을 고를지 규칙을 만들고, 홀수 Seed에서는 이미 고정한 규칙이 잘 작동하는지 확인합니다. 같은 문제를 보고 규칙을 정하고 점수까지 매기면 유리하게 평가될 수 있습니다.

같은 Seed의 출발점 변형과 반사 쌍은 서로 관련되어 있어 한쪽 그룹에 함께 둡니다. 다만 같은 숫자 Seed를 공유하는 모든 배치가 동일한 위치에서 파생되는 것은 아닙니다. 기본 패턴마다 별도의 추첨 기준을 사용합니다.

12. 선택 규칙 — 어떤 방법을 고를까요?

개발 데이터에서 전체 작업을 예산 안에 완료한 고정 방법을 찾고, 특징 하나와 경계값 하나로 두 그룹을 나누는 규칙도 비교합니다. 각 그룹에서는 모든 학습 작업을 완료한 방법 중 총 이동 거리가 가장 작은 것을 선택합니다. 개발 그룹 교차검증 뒤 전체 개발 데이터로 최종 규칙을 저장합니다.

항상 NN+2-opt

개수 규칙

특징 확장

숫자 특징 / 패턴까지 허용했지만 최종 규칙은 동일

프로젝트 검토에서 무엇을 더 확인하라고 했나요?

현재 확인한 범위에서 기본 구현과 테스트는 갖춰져 있습니다. 다음 보완은 선택 규칙을 설명하는 근거를 더 분명하게 만드는 작업입니다.

  1. 입증 범위: 여러 특성을 후보로 비교했지만 최종 규칙은 조건 하나만 사용합니다. “물건이 많으면서 분산도가 높은 경우”처럼 두 조건의 조합은 표현하지 못합니다. 추가 특성이 일반적으로 필요 없다는 결론까지 확대하지 않습니다.
  2. 경계 실험: n=12는 완료했고 n=15는 시간 초과였지만 n=13·14는 측정하지 않았습니다. 이 구간과 시간 예산별 완료율을 더 확인하면 선택 기준을 설명하기 좋습니다.
  3. 실제 시간: 현재 정책 평가에는 고정 방법에도 전체 특성 계산을 시키고 거리 전처리를 중복하는 부분이 있습니다. 각 방법에 필요한 계산만 포함한 전체 시간을 추가 비교할 필요가 있습니다.

규칙을 수정한다면 개발 데이터로 정하고 새 평가 Seed에서 확인합니다. 이미 본 평가 자료를 이용한 조건 탐색은 탐색 분석으로 구분합니다.

평가 정책 원자료의 평균 이동거리는 고정 NN+2-opt가 168.29m, 개수 규칙이 166.86m입니다. 작업당 평균 약 1.43m 절감이며, 고정 정책의 전체 이동거리 대비로는 약 0.85%입니다. 위 표의 중앙값 156m·152m와는 서로 다른 통계입니다.

컨베이어 고려 후보도 전체 평균과 개별 승패를 함께 볼 필요가 있습니다. 계수 0.5의 CA-minus+2-opt는 NN+2-opt보다 평균 약 0.99m 길었지만, 같은 평가 작업 2,025건 중 282건은 더 짧고 1,357건은 같으며 386건은 더 길었습니다. 어느 조건에서 이겼는지를 분석할 여지는 있습니다.

이 수치는 저장된 실험 자료의 재집계입니다. 실제 작업자 이동 속도·집는 시간·혼잡을 측정하지 않았으므로 생산성이나 노동시간 절감으로 바로 환산하지 않습니다. 보완 사항은 검토 의견이며 추가 실험이 완료됐다는 뜻이 아닙니다.

Seed배치를 뽑을 때 사용한 추첨 번호같은 배치 유형과 위치 수에서 다른 예제를 찾을 수 있습니다. ‘전체’는 여러 Seed를 함께 조회합니다.
작업 ID출발점과 방문 위치가 확정된 주문 하나의 이름표구체적으로 비교할 작업을 선택합니다.
101:3:clustered:0
Seed 101 · 방문 위치 3곳 · 군집형 · 출발점 번호 0

출발점 번호는 0=앞쪽 (0,0), 1=중앙 (16,20), 2=가장자리 (0,40)입니다. 알고리즘끼리 비교할 때는 작업 ID를 그대로 두고 알고리즘만 바꾸세요. F와 H는 각각 반사 배치와 출발점 변화를 보기 위해 짝 작업을 비교하는 예외입니다.

화면에서 Seed를 바꾸면 저장된 작업을 찾아 보여줍니다. 새 배치를 즉석에서 만들지 않습니다. ‘선택한 경로 재계산’도 현재 작업의 물건 위치는 유지하고 선택한 알고리즘을 다시 실행합니다.

A–H 상황을 왜 따로 나눴나요?

물건 배치는 데이터를 만드는 조건이고, A–H는 결과에 던지는 질문입니다. A–H는 서로 겹치는 실험 관점입니다. 예를 들어 같은 군집형 작업을 작은 문제의 정확성 확인에도, 경로 개선 확인에도 사용할 수 있습니다. 버튼을 누르면 그 질문에 맞는 위치 수·배치·출발점·비교 알고리즘이 기본값으로 선택됩니다.

상황왜 따로 보는가?기본 비교와 발표 문장
A 정확성성능을 논하기 전에 정답을 구하는 코드가 서로 일치하는지 확인합니다.작은 작업의 완전 탐색 / DP. “먼저 두 정확한 방법이 같은 최단 거리를 내는지 확인했습니다.”
B 계산 규모정확한 방법의 계산 비용이 물건 수에 따라 어떻게 커지는지 봅니다.기본 n=15의 DP / NN+2-opt. “정확해가 좋아도 시간 안에 계산할 수 있는지 따로 확인했습니다.”
C 큰 작업빠른 방법을 써야 하는 규모에서 경로를 얼마나 개선할 수 있는지 봅니다.기본 n=50의 NN / NN+2-opt. “빠른 초기 경로에 순서 개선을 더한 효과를 비교했습니다.”
D 군집 배치물건이 한 구역에 모인 조건에서도 가까운 순서가 충분한지 봅니다.기본 n=10 군집형의 NN / NN+2-opt. “물건 수 외에 모여 있는 형태도 함께 살펴봤습니다.”
E 분산도군집·무작위라는 이름을 넘어 실제로 물건들이 얼마나 떨어졌는지 봅니다.기본 n=10 전체 무작위형의 NN / NN+2-opt. “물건 사이 평균 통로 거리와 개선 폭을 함께 읽었습니다.”
F 도착점 관계물건 간 구조를 유지한 반사 쌍으로 위치 관계가 달라진 결과를 봅니다.같은 NN의 far / near 작업. “구조가 같아도 도착점과 출발점에 대한 위치 관계는 달라집니다.”
G 방향·패턴뒤쪽 물건을 수집한 뒤 고정 컨베이어로 와야 하는 조건에서 도착점 고려 후보를 봅니다.기본 n=10 방향형의 NN / CA-minus. “컨베이어까지의 거리를 탐욕 점수에 넣으면 어떤 차이가 나는지 비교했습니다.”
H 출발점 변경물건이 같아도 작업자가 어디서 출발하느냐에 따라 결과가 바뀌는지 봅니다.같은 NN과 물건 집합의 출발점 짝. “물건 위치를 유지하고 출발점만 바꿨습니다.”

발표 흐름은 A로 정확성 → B·C로 계산 규모 → D·E로 공간 분포 → F·G·H로 출발·도착 관계 순서로 묶으면 이해하기 쉽습니다. 모든 상황을 시연할 필요는 없으며, 주장에 필요한 사례와 전체 집계를 연결해 보여주면 됩니다.

시나리오 버튼은 비교 시작점을 잡아주는 도구입니다. E는 분산도를 독립적으로 조절하는 실험이 아니며, F는 출발점 거리도 바뀝니다. 화면의 기본 예제 한 건으로 전체 경향이나 인과관계를 주장하지 않습니다. B의 시간 초과와 크기 제한도 구분해야 합니다.

17. 예상 질문과 이해 확인

다익스트라로 최단 경로를 구했는데 왜 DP가 또 필요한가요?

다익스트라는 두 위치 사이의 길을 구합니다. DP는 여러 물건 위치를 어떤 순서로 방문할지 정합니다. 두 문제를 나눴습니다.

이것은 TSP인가요?

여러 위치를 모두 방문한다는 점에서 TSP와 관련됩니다. 다만 시작점과 끝점이 정해진 열린 경로 문제이고, 끝난 뒤 출발점으로 돌아오는 비용은 없습니다.

왜 NN을 쓰면 안 되나요?

매 순간 가까운 곳을 고르는 선택은 빠르지만 마지막 도착점까지 포함한 전체 거리를 최소화하지 않을 수 있습니다. 기준 방법으로 사용하고 개선 및 정확한 방법과 비교했습니다.

DP도 모든 순서를 보는 건가요?

방문 집합과 마지막 위치가 같은 상태를 합쳐 중복 계산을 줄입니다. n! 순서를 그대로 나열하는 대신 약 n×2ⁿ개의 상태를 사용하지만, 여전히 지수적으로 커집니다.

2-opt면 최적해를 찾는 건가요?

아닙니다. 구간 뒤집기만으로 더 좋아지지 않는 지역 최적점일 수 있습니다. 평가 한도나 시간 제한에 먼저 도달할 수도 있습니다.

CA-minus를 새 알고리즘이라고 주장하나요?

컨베이어 거리를 반영한 탐욕 후보로 비교했습니다. 일반적인 최적성이나 보편적인 우월성, 새로운 알고리즘이라는 검증된 주장을 하지 않습니다.

왜 13.5인가요?

개발 표본의 12와 15 사이에서 총 거리와 완료 조건을 만족하는 경계로 골라졌습니다. 보편 상수가 아니며 다른 환경에서는 달라질 수 있습니다.

왜 최적 거리인데 DP의 전체 중앙값이 다르게 보이나요?

완료한 작업 집합이 다르면 전체 중앙값의 비교 대상도 다릅니다. 같은 작업끼리 비교하거나 위치 수별로 확인하고 완료율을 함께 보여야 합니다.

1.43m는 어떻게 계산했나요?

같은 평가 작업에서 고정 NN+2-opt 거리에서 개수 규칙 거리를 뺀 뒤, 2,025개 차이를 평균했습니다. 거리 중앙값 156과 152를 뺀 4m와는 다른 값입니다.

추가 특징이 도움이 됐나요?

이번에는 숫자·패턴을 추가해도 개수 규칙과 동일한 규칙이 나왔습니다. 추가 이득을 확인하지 못했습니다. 다른 표본에서도 전혀 쓸모없다는 뜻은 아닙니다.

시간 초과인데 왜 경로가 나오나요?

요청 후보가 중단돼도 미리 확보한 NN이나 후보의 중간 유효 경로가 반환될 수 있습니다. requested status와 returned algorithm을 구분해서 보고합니다.

실제 물류센터에도 그대로 적용할 수 있나요?

아직은 합성 창고와 작업 분포입니다. 혼잡, 여러 작업자, 적재량, 일방통행, 서비스 시간을 다루지 않아 실제 환경에서 추가 검증이 필요합니다.

2,025개의 완전히 독립적인 평가인가요?

같은 seed에서 여러 배치·출발점 변형이 나옵니다. 그래서 독립 재표본추출 단위는 15개 seed 그룹으로 두고 관련 작업을 묶어 신뢰구간을 구했습니다.

자동 선택은 웹 요청에 연결되어 있나요?

선택 규칙의 학습과 오프라인 평가는 구현되어 있습니다. 일반 run_request는 알고리즘 이름을 직접 받으며 규칙을 자동 적용하는 형태로 통합되어 있지 않습니다.

실제 작업 시간은 얼마나 줄었나요?

현재는 이동 거리와 계산 시간을 측정했습니다. 작업자 속도·집는 시간·혼잡을 측정하지 않았으므로 실제 작업 시간 절감을 수치로 주장할 수 없습니다.

7def group_interval(group_values, seed=0, repetitions=1000):
8    """Bootstrap groups, keeping all related tasks together."""
9    groups = list(group_values.values())
10    if len(groups) < 2:
11        return None
12    rng = random.Random(seed)
13    samples = []
14    for _ in range(repetitions):
15        picked = [groups[rng.randrange(len(groups))] for _ in groups]
16        samples.append(mean(value for group in picked for value in group))
17    samples.sort()
18    return [samples[int(.025 * repetitions)], samples[int(.975 * repetitions) - 1]]

84def train(rows, *, cross_validate=True):
85    """Fit interpretable one-threshold rules using development records only.
86
87    A candidate must complete every training task; this avoids rewarding failures.
88    Rules are resubstitution fits, not a claim of generalization.
89    """
90    if not rows or any(r["task"]["split"] != "dev" or r["mode"] != "request" for r in rows):
91        raise ValueError("training requires development-only request records")
92    tasks = defaultdict(dict)
93    for row in rows:
94        tasks[row["task"]["id"]][row["algorithm"]] = row
95    budgets = {r["budget_seconds"] for r in rows}
96    coefficients = {r["coefficient"] for r in rows}
97    limit_sets = {tuple(sorted(r["limits"].items())) for r in rows}
98    sources = {r["environment"]["source_sha256"] for r in rows}
99    if len(budgets) != 1 or len(coefficients) != 1 or len(limit_sets) != 1 or len(sources) != 1:
100        raise ValueError("training requires one budget and coefficient")
101    names = set.intersection(*(set(x) for x in tasks.values()))
102    def choose(ids):
103        scores = []
104        for name in sorted(names):
105            results = [tasks[i][name]["result"] for i in ids]
106            if all(r["status"] == "completed" and r.get("distance") is not None and not r.get("budget_exceeded", False) for r in results):
107                scores.append((sum(r["distance"] for r in results), name))
108        if not scores:
109            raise ValueError("no candidate completed every training task within budget")
110        return min(scores)
111    ids = sorted(tasks)
112    fixed_score, fixed = choose(ids)
113    rules = {"fixed": {"algorithm": fixed}}
114    feature_sets = {"count": ["n"], "numeric": ["n", "dispersion", "start_mean", "conveyor_mean"],
115                    "numeric_pattern": ["n", "dispersion", "start_mean", "conveyor_mean", "pattern"]}
116    for label, fields in feature_sets.items():
117        best = (fixed_score, {"algorithm": fixed})
118        for field in fields:
119            values = {i: next(iter(tasks[i].values()))["features"][field] for i in ids}
120            distinct = sorted(set(values.values()))
121            if field == "pattern":
122                thresholds = distinct
123            else:
124                indices = sorted({min(len(distinct)-2, int((len(distinct)-1)*q/10)) for q in range(1, 10)}) if len(distinct) > 1 else []
125                thresholds = [(distinct[i]+distinct[i+1])/2 for i in indices]
126            for threshold in thresholds:
127                left = [i for i in ids if values[i] == threshold] if field == "pattern" else [i for i in ids if values[i] <= threshold]
128                left_set = set(left)
129                right = [i for i in ids if i not in left_set]
130                if not left or not right:
131                    continue
132                try:
133                    lscore, lalg = choose(left)
134                    rscore, ralg = choose(right)
135                except ValueError:
136                    continue
137                if lscore + rscore < best[0] - 1e-9:
138                    best = (lscore + rscore, {"feature": field, "threshold": threshold, "left": lalg, "right": ralg})
139        rules[label] = best[1]
140    groups = sorted({r['task']['group'] for r in rows})
141    cv = {}
142    if cross_validate and len(groups) >= 2:
143        folds = min(3, len(groups))
144        scores = {name: [] for name in rules}
145        failures = Counter()
146        for fold in range(folds):
147            held = set(groups[fold::folds])
148            fit = train([r for r in rows if r["task"]["group"] not in held], cross_validate=False)
149            validation = [r for r in rows if r["task"]["group"] in held]
150            for name, rule in fit["rules"].items():
151                for row in validation:
152                    if row["algorithm"] != select(rule, row["features"]):
153                        continue
154                    result = row["result"]
155                    if result["status"] == "completed" and result.get("distance") is not None and not result.get("budget_exceeded", False):
156                        scores[name].append(result["distance"])
157                    else:
158                        failures[name] += 1
159        cv = {name: {"completed": len(values), "failures": failures[name],
160                     "mean_distance_m": mean(values) if values else None} for name, values in scores.items()}
161    return {"rules": rules, "training_task_count": len(ids), "training_groups": groups,
162            "budget_seconds": next(iter(budgets)), "coefficient": next(iter(coefficients)),
163            "limits": dict(next(iter(limit_sets))), "source_sha256": next(iter(sources)),
164            "group_cross_validation": cv,
165            "note": "Rules fitted on all development data after grouped CV; pattern is synthetic metadata."}

85def _subset_dp(table: DistanceTable, limits: Limits,
86               deadline: float | None) -> AlgorithmResult:
87    points = tuple(sorted(table.task.internal))
88    n = len(points)
89    if n == 0:
90        return _result(table, "dp", (), optimal=True, dp_buffer_bytes=0)
91    cells = n * (1 << n)
92    buffer_bytes = cells * (array("d").itemsize + array("i").itemsize)
93    if buffer_bytes > limits.dp_memory_bytes:
94        return _result(table, "dp", None, status="resource_limit", termination="dp_memory_estimate",
95                       dp_buffer_bytes=buffer_bytes)
96    check_deadline(deadline)
97    try:
98        costs, parents = array("d", [inf]) * cells, array("i", [-1]) * cells
99    except (MemoryError, OverflowError):
100        return _result(table, "dp", None, status="resource_limit", termination="allocation_failed",
101                       dp_buffer_bytes=buffer_bytes)
102    for j, point in enumerate(points):
103        costs[(1 << j) * n + j] = table.d(table.task.start, point)
104    for mask in range(1, 1 << n):
105        check_deadline(deadline)
106        for j in range(n):
107            if not mask & (1 << j):
108                continue
109            previous_mask = mask ^ (1 << j)
110            if previous_mask == 0:
111                continue
112            remaining, best, parent = previous_mask, inf, -1
113            while remaining:
114                bit = remaining & -remaining
115                i = bit.bit_length() - 1
116                candidate = costs[previous_mask * n + i] + table.d(points[i], points[j])
117                if candidate < best:
118                    best, parent = candidate, i
119                remaining ^= bit
120            costs[mask * n + j], parents[mask * n + j] = best, parent
121    check_deadline(deadline)
122    full = (1 << n) - 1
123    last = min(range(n), key=lambda j: (costs[full * n + j] + table.d(points[j], table.task.conveyor), j))
124    order, mask = [], full
125    while last != -1:
126        order.append(points[last])
127        previous = parents[mask * n + last]
128        mask ^= 1 << last
129        last = previous
130    check_deadline(deadline)
131    return _result(table, "dp", tuple(reversed(order)), optimal=True, dp_buffer_bytes=buffer_bytes)

134def two_opt(table: DistanceTable, initial: AlgorithmResult, *,
135            max_evaluations: int = 10_000, deadline: float | None = None,
136            epsilon: float = 1e-9) -> AlgorithmResult:
137    """무방향 거리 전용. 첫 개선 후 다시 탐색하며 최선의 유효 경로를 유지한다."""
138    if initial.order is None:
139        raise InputError("2-opt에는 유효한 초기 방문 순서가 필요합니다.")
140    if (isinstance(max_evaluations, bool) or not isinstance(max_evaluations, int)
141            or max_evaluations < 0 or not isfinite(epsilon) or epsilon < 0):
142        raise InputError("2-opt 한도·허용 오차가 잘못되었습니다.")
143    order = list(table.validate_order(initial.order))
144    initial_distance = distance = _cost(table, order)
145    evaluated, improvements, status, reason = 0, 0, "completed", "local_optimum"
146    try:
147        while True:
148            check_deadline(deadline)
149            improved = False
150            for i in range(len(order) - 1):
151                for j in range(i + 1, len(order)):
152                    check_deadline(deadline)
153                    if evaluated >= max_evaluations:
154                        reason = "evaluation_limit"
155                        break
156                    before = table.task.start if i == 0 else order[i - 1]
157                    after = table.task.conveyor if j == len(order) - 1 else order[j + 1]
158                    delta = (table.d(before, order[j]) + table.d(order[i], after)
159                             - table.d(before, order[i]) - table.d(order[j], after))
160                    evaluated += 1
161                    if delta < -epsilon:
162                        candidate = order[:i] + list(reversed(order[i:j + 1])) + order[j + 1:]
163                        candidate_distance = _cost(table, candidate)
164                        if candidate_distance < distance - epsilon:
165                            order, distance = candidate, candidate_distance
166                            improvements += 1
167                            improved = True
168                            break
169                if improved or reason == "evaluation_limit":
170                    break
171            if not improved:
172                break
173    except DeadlineExceeded:
174        status, reason = "timeout", "deadline"
175    return _result(table, initial.algorithm + "+2opt", tuple(order), status=status,
176                   termination=reason, initial_distance=initial_distance,
177                   evaluated_moves=evaluated, accepted_moves=improvements,
178                   initial_settings=initial.details)

53@dataclass(frozen=True)
54class DistanceTable:
55    graph: Graph
56    task: Task
57    matrix: Mapping[Node, Mapping[Node, float]]
58    predecessors: Mapping[Node, Mapping[Node, Node]]
59
60    def d(self, u: Node, v: Node) -> float:
61        return self.matrix[u][v]
62
63    def leg(self, u: Node, v: Node) -> tuple[Node, ...]:
64        self.d(u, v)  # 전처리된 위치만 허용한다.
65        path = [v]
66        while path[-1] != u:
67            path.append(self.predecessors[u][path[-1]])
68        return tuple(reversed(path))
69
70    def validate_order(self, order: Iterable[Node]) -> tuple[Node, ...]:
71        order = tuple(order)
72        if len(order) != len(self.task.internal) or set(order) != set(self.task.internal):
73            raise InputError("방문 순서는 내부 필수 위치를 중복 없이 포함해야 합니다.")
74        return order
75
76    def route_distance(self, order: Iterable[Node]) -> float:
77        order = self.validate_order(order)
78        stops = (self.task.start, *order, self.task.conveyor)
79        return sum(self.d(u, v) for u, v in zip(stops, stops[1:]))
80
81    def reconstruct(self, order: Iterable[Node]) -> tuple[Node, ...]:
82        order = self.validate_order(order)
83        stops = (self.task.start, *order, self.task.conveyor)
84        path = [stops[0]]
85        for u, v in zip(stops, stops[1:]):
86            path.extend(self.leg(u, v)[1:])
87        return tuple(path)
88
89    def validate_path(self, order: Iterable[Node], path: Iterable[Node],
90                      reported_distance: float) -> None:
91        order, path = self.validate_order(order), tuple(path)
92        if not path or path[0] != self.task.start or path[-1] != self.task.conveyor:
93            raise InputError("실제 경로의 시작 또는 끝이 잘못되었습니다.")
94        if not set(self.task.required).issubset(path):
95            raise InputError("실제 경로가 필수 위치를 빠뜨렸습니다.")
96        try:
97            length = sum(self.graph.adjacency[u][v] for u, v in zip(path, path[1:]))
98        except KeyError as exc:
99            raise InputError("실제 경로에 없는 통로가 포함되었습니다.") from exc
100        if not isfinite(reported_distance) or not (
101            isclose(length, reported_distance, rel_tol=1e-12, abs_tol=1e-9)
102            and isclose(length, self.route_distance(order), rel_tol=1e-12, abs_tol=1e-9)
103        ):
104            raise InputError("보고 거리, 방문 순서 거리, 실제 통로 길이가 다릅니다.")

107def dijkstra(graph: Graph, source: Node, deadline: float | None = None,
108             clock_check: Callable[[float | None], None] = check_deadline
109             ) -> tuple[dict[Node, float], dict[Node, Node]]:
110    if source not in graph.adjacency:
111        raise InputError("출발 노드가 지도에 없습니다.")
112    distances, previous = {source: 0.0}, {}
113    queue = [(0.0, source)]
114    while queue:
115        clock_check(deadline)
116        distance, u = heappop(queue)
117        if distance != distances[u]:
118            continue
119        for v, weight in graph.adjacency[u].items():
120            candidate = distance + weight
121            if candidate < distances.get(v, inf):
122                distances[v], previous[v] = candidate, u
123                heappush(queue, (candidate, v))
124    return distances, previous

127def prepare_distances(graph: Graph, task: Task,
128                      deadline: float | None = None) -> DistanceTable:
129    if task.conveyor != graph.conveyor:
130        raise InputError("작업의 컨베이어가 환경과 다릅니다.")
131    locations = tuple(sorted({task.start, task.conveyor, *task.required}))
132    matrix, predecessors = {}, {}
133    for source in locations:
134        distances, previous = dijkstra(graph, source, deadline)
135        if any(target not in distances for target in locations):
136            raise UnreachableError("S, 필수 위치, C가 같은 연결 요소에 있어야 합니다.")
137        matrix[source] = MappingProxyType({p: distances[p] for p in locations})
138        predecessors[source] = MappingProxyType(previous)
139    return DistanceTable(graph, task, MappingProxyType(matrix), MappingProxyType(predecessors))

35def make_graph(nodes: Iterable[Node], edges: Iterable[tuple[Node, Node, float]],

41    지도는 기하적 선반 정보가 없으므로 간선의 물리적 의미까지 추론하지 않는다.

62                               for n, neighbors in sorted(adjacency.items())})

30def run_request(graph: Graph, start: Node, required: Iterable[Node], algorithm: str = "nn", *,
