한 곳씩 → 6곳 묶음
순서 개선

우리가 제안한 알고리즘은 선반이 많을 때 빠르게 만든 방문 경로를 두 단계로 다듬습니다. 선반 하나의 순서를 먼저 옮겨 보고, 이어서 연속한 여섯 곳의 순서를 함께 바꿉니다.

경로는 어떻게 짧아지나요?

방문할 선반이 많으면 모든 방문 순서를 비교하기 어렵습니다. 그래서 가까운 선반부터 방문하고 중간 구간을 뒤집어 거리를 줄이는 NN + 2-opt로 먼저 경로를 만든 뒤, 아래 두 단계를 적용합니다.

  1. 한 곳씩 순서 개선

    선반 하나를 빼서 다른 방문 순서에 넣어 봅니다. 전체 거리를 가장 많이 줄이는 자리가 있으면 그곳으로 옮깁니다. 이 과정이 재삽입입니다.

  2. 6곳 묶음 순서 개선

    현재 순서에서 연속한 여섯 선반을 고릅니다. 묶음의 앞뒤 경계를 고정하고 여섯 곳을 가장 짧게 도는 순서를 계산합니다. 묶음을 세 자리씩 옮기며 반복합니다. 이 계산에 구간 DP를 사용합니다.

예를 들어 먼저 8번째 선반을 3번째에 들르면 더 짧아지는지 봅니다. 다음에는 3~8번째에 놓인 선반 여섯 곳의 순서를 함께 다시 짭니다. 두 단계 모두 전체 거리가 줄어드는 변경만 적용합니다.

두 번째 단계가 도움이 됐나요?

선반 15·20·50곳을 방문하는 합성 작업 1,350건을 비교했습니다. 재삽입을 두 번 수행한 경우를 함께 측정해, 두 번째에 여섯 곳을 함께 바꾸는 효과를 확인했습니다.

제안 알고리즘 · 한 곳씩 → 6곳 묶음 순서 개선226.64m3.44ms

제안 방법은 기존 경로보다 평균 1.68m, 한 곳씩 두 번 고친 경로보다 평균 0.41m 짧았습니다. 60개 작업을 네 방법으로 10번씩 반복한 별도 측정에서도 2,400회 모두 200ms 안에 끝났습니다.

실행 시간은 컴퓨터가 입력을 준비하고, 알고리즘을 돌려 경로를 계산하고, 그 경로를 복원·검증하는 데 걸린 시간입니다. 예를 들어 3.44ms는 전체 작업의 절반 정도가 3.44ms 이내에 처리됐다는 뜻입니다. 합성 창고 한 곳에서 측정했습니다.

데모에서 직접 비교하기

  1. 프로젝트 폴더에서 python3 -m demo --port 8766을 실행하고 브라우저에서 http://127.0.0.1:8766을 엽니다.
  2. 시나리오 I ‘제안 알고리즘’을 선택합니다. 두 방법이 자동으로 선택되고, 선택한 새 알고리즘의 설명이 나타납니다.
  3. ‘선택한 경로 재계산’을 누른 뒤 지도와 이동 거리를 비교합니다. 기본 예시에서 재삽입 두 번은 248m, 제안 방법은 240m였습니다.
